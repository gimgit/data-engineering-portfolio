Spark on EKS / Karpenter compute and scheduling optimization
08/2026 - Present
Problem
After stopping a cost leak, the executor fleet still cost ~$830/day. Planned memory utilization was below 45% on 81% of large nodes; the long-job pool lacked Spot capacity.
Analysis
Separated memory, CPU, disk and churn using a 41-application heap census and 775 event logs. Found that 100Gi scratch requests on fixed 512Gi EBS volumes capped every node at four Pods, regardless of instance size.
Decisions
Rejected four alternatives using measurements. Added an NVMe instance-store pool with EBS fallback, reduced executor memory from 32g to 24g, and broadened instance-family fallback for long jobs.
Results
Verified 3.2x allocatable ephemeral storage and removal of the four-Pod cap in production. Long-job launch failures fell from 69-82% to 26% / 2% in observed windows. Quantified ~$2.1K/month in sparse-node overpayment; realized savings remain under validation.
Tools
EKS · Karpenter · EC2 Spot · NVMe instance store · EBS · Spark · Terraform · Datadog

Kafka Connect CDC correctness and recovery
11/2025 - Present
Problem
Source stalls, zombie coordinators and merge-window defects silently lost data even when connectors were RUNNING and consumer lag was zero.
Decisions
Defined end-to-end liveness through commit age, freshness and source-target parity. Applied snapshot watermarks, idempotent anti-join backfills and an Iceberg sink runtime upgrade.
Results
Recovered quantified losses of up to ~355K rows, verified through exact reconciliation. Validated CDC ingestion of 12M+ consent documents for regulatory requirements with zero duplicates and zero dead-letter queue (DLQ) entries.
Practice
Stopped treating lag=0 or RUNNING status as proof of health. Required natural-key and anti-join idempotency for at-least-once replay.
